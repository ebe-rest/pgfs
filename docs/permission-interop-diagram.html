PGFS Permission / Ownership / ACL Interop Diagram

Windows (attributes + ACL) ↔ PGFS canonical store ↔ Linux (permissions + POSIX ACL) / design reference: docs/permission-interop.md

This diagram captures the agreed design (10 items). POSIX is the canonical model and the Windows ACL is a projection view (deny ACEs, ACE ordering, and inheritance flags are not adopted — they are dropped on projection). GetFileSecurity/SetFileSecurity project and reverse-project between the inode (mode + canonical ACL) and the Windows security descriptor; the Linux side round-trips the same canonical store via system.posix_acl_access. Design reference: docs/permission-interop.md.
Name normalization (shared across all principals — ★ core) — the same normalization is applied to owner / group / principal names both when storing and when matching, and also to the caller (the access subject) name.

The Agreed Design (10 Items)

  1. [1] Name normalization — on store, on match, and on the caller name: strip domain + full-width ASCII → half-width + lowercase. Even on Linux, alice=Alice=Ａlice are treated as identical.
  2. [2] Domain stripping — strip both \ (NetBIOS) and @domain (UPN).
  3. [3] Principal mapping — full bidirectional. The DB stores Linux names. See the table below.
  4. [4] Windows ACL = projection view — POSIX is canonical; Windows-specific features (deny / ACE order / inheritance) are not adopted and are dropped on projection (opaque was removed).
  5. [5] ACL model — POSIX-only / allow only. acl[]={principal_type, principal_name, rights}, with mode + acl[] coexisting.
  6. [6] Windows attributes — JSON {hidden,system,archive} in user.win.attrs (user namespace). compressed is future work.
  7. [7] ReadOnly — if the access subject itself cannot write, it is ReadOnly (owner/group/other writable is evaluated against the normalized caller).
  8. [8] owner=group — when Windows sets a group as the owner → owner=nobody / group=that group.
  9. [9] Anonymous access — unsupported (policy statement only, no code change). nobody is the evaluation result of an unresolved principal, not an authorization of anonymous access.
  10. [10] ACL evaluation — POSIX-order evaluation in the client driver (owner→named user→group/named group→other). Linux also evaluates in the pgfs layer with normalization rather than delegating to the kernel.

Implementation status: all 10 decisions are implemented, except that strict named-ACL enforcement and system.posix_acl_default → Windows inheritance are deferred until requirements arrive.

Worked Example: Setting the owner to "Users" on Windows

Premise: Linux has user user / group users (there is no user Users).

ApproachBehavior
Naive impl
(uname as-is)		Stores uname=Users → Linux resolves the owner via getpwnam("Users") → (a) Users is a group but is looked up as a user / (b) case-sensitivity also mismatches user → appears as nobody (the information intended for group users is lost)
Agreed design
(this diagram)		The Windows owner is detected as a group SID [8] → owner_name=nobody / group_name=users (normalization turns Users→users [1]). Linux: owner=nobody / group=users (getgrnam resolution). Windows re-render: owner=projection of ANONYMOUS LOGON [3] / group=Users. → group info is preserved and case is absorbed
