## What this document is for

**The instruction**: **among the things hit so far, turn the ones that were fixed but were "a choice rather
than a bug" into options**, and **make all of it, including what v0.3.0 adds, configurable in detail from the
GUI**.

It is settled that **this is not part of v0.2.0** ([next.md](../next.md)).

## The classification marks

**The GUI-side effort is much the same for all of them, but the Core-side effort differs completely**, hence
the split.

| Mark | Meaning | The Core-side work |
|---|---|---|
| **(1)-a** | Fixed today, but **an internal flag already exists** | **Just promote it to a settings item** |
| **(1)-b** | Fixed today, and **there is no branch at all** | **Create the branch.** It needs both an implementation and a regression |
| **(2)** | **Already a settings item, but the choice of default was itself a choice** | **The default and the documentation only.** The branch already exists |

## The candidates (gathered from the Linux / shared Core side)

**Gathered from the documents rather than from memory.** The method was to `git grep` every document for the
phrases used when something was chosen deliberately or deliberately not taken, and to keep **only the ones
that change behaviour as the user sees it** (exceptions to the naming convention and coding-convention
matters were dropped).

**The key names are proposals and are not implemented anywhere yet.**

### (2) - the choice of default was itself a choice

| Candidate | Key (existing) | Default | What the choice was |
|---|---|---|---|
| **`mount.fallback_gname`** | `mount.fallback_gname` | `nogroup` | **el9 has no `nogroup`** (the RHEL family uses `nobody`). **Every mount prints a warning and falls back to the hardcoded gid 65534.** **Either vary the default by distribution, or settle on `nobody`** |
| **`mount.fallback_uname`** | `mount.fallback_uname` | `nobody` | The pair of the above. This one exists on el9 as well |
| **`database.notify_enabled`** | `database.notify_enabled` | `false` | **Effectively mandatory if several mounts are used on Windows** ([CHANGELOG.md, the known limitations](../../CHANGELOG.md)). **Either vary the default by operating system, or detect several mounts and warn** |
| **`mount.write_back`** | `mount.write_back` | `false` | Off, because **whatever is unflushed is lost on a crash**. **The cross-client trampling also happens only while this is on** |
| **`mount.write_back_metadata`** | `mount.write_back_metadata` | `false` | Off, because **the audit stops being durable** ([audit-log.md](audit-log.md)). The documentation requires **leaving it off in any deployment that uses the audit as evidence** |
| **`filesystem.cluster_size`** | `filesystem.cluster_size` | 1 MiB | **This value is the extent lost to the trampling** (it happens per chunk). **A smaller value reduces the damage and increases the number of txs** |
| **Not persisting `database.connection`** | `database.connection` | `SaveTo=None` | **Deliberately discarded for the safety of the credentials** ([settings-matrix.md](settings-matrix.md)). The trade is **having to give it again on every re-mkfs** |

## The candidates (gathered from the Windows side)

**Re-checking the six the Linux side listed against the implementation left four candidates and two "do not
add" cases.**
**The method was the same as on the Linux side** (start from where the documents say something was
deliberate or was a ruling, then confirm it in the implementation).

### (1)-b - creating a new branch

| Candidate | Proposed key | CLI | TOML | DB | Default | Type | When it is read | Note |
|---|---|---|---|---|---|---|---|---|
| **Whether reserved names and trailing spaces/dots are rejected at the entrance** | `assign.reject_invalid_windows_names` | `--reject-invalid-names` | ✅ | ❌ | `true` | bool | In `CreateFile` (**only on a new creation**) | **Existing ones can be opened** under the current ruling ([namespace-policy.md](namespace-policy.md)), so that **a name created from Linux does not become unreadable on Windows**. **Turning it off allows creating `NUL` and `dot.`**, but **produces files that many Win32 APIs cannot touch**. The regression is the three `test_ns_*` tests in the Windows e2e |
| **Whether a new file's group is inherited from the parent or taken from the creator's primary group** | `assign.new_file_group` | `--new-file-group` | ✅ | ❌ | `inherit_parent` | enum (`inherit_parent` / `creator_primary`) | In `DoCreate` (at creation) | **The ruling** ([windows-parity.md](windows-parity.md)). | **Whether the domain part is stripped from an owner name** | `mount.owner_name_domain` | `--owner-name-domain` | ✅ | ❌ | `strip` | enum (`strip` / `keep`) | When an owner name is normalized (`NameNormalizer.Normalize`) | **`CORP\alice` and `LOCAL\alice` collapse into the same `alice`** (a known point in [tests.md](../tests.md)). **Tipping it to `keep` makes the uname seen from Linux `CORP\alice`, which is unusable as a POSIX uname** - **it only means something where names collide in a domain environment**. ⚠ **The implementation is `src/core/src/Utility/NameNormalizer.cs` and applies to both operating systems**, so **the scope is `mount.` rather than `assign.`** (it spans both owners) |
| **Whether `mkdir` is write-through** | `mount.mkdir_write_through` | `--mkdir-write-through` | ✅ | ❌ | `false` | bool | In `CreateDirectory` (**only in effect while `write_back_metadata` is on**) | **A settled specification** ([windows-parity.md, on not making `mkdir` synchronous](windows-parity.md)). **Making it synchronous means no pending directory can come into existence in principle, which turns the ancestor-chain INSERT and the adoption of an existing id for dir/dir (Rekey) into unreachable code.** `test_meta_exclusive_create_is_write_through` in `wbmeta.sh` pins that ruling down. **If it is opened up, the documentation must say that a path becomes unreachable** |

### The Windows-side things that are **not** candidates

| Dropped from the candidates | Why |
|---|---|
| **The formula of `FileIndex`** (`data_id \| 0x8000...`) | **Being the same formula as Linux's `st_ino` is the premise of deciding that hardlink siblings are the same file.** **Making it a setting that can be changed on one side alone would allow the broken combination "a different file from Windows, the same file from Linux".** **It is an invariant, not a choice.** |
| **Which bits ReadOnly touches in `SetFileAttributes`** | **The alternative to the current behaviour (touching the write bits only) is exactly the bug that was fixed** (rebuilding to `0444`/`0644`/`0755` = **the traverse right of a directory is dropped**). **It is a fix, not a choice**, so it is not included. The regression is `test_readonly_dir_keeps_execute` |

## Configuring it from the GUI (extending the GUI's config-set step - **a design proposal**)

A proposal for the second half of the instruction: "**make all of it, including what v0.3.0 adds,
configurable in detail from the GUI**".
**It is not agreed yet** and nothing is implemented. **[gui.md](gui.md) is the source of truth for the GUI's
design itself**, and this document holds **only "how the v0.3.0 items are shown"**.

The foundation is the config-set step of [gui.md](gui.md) (config set from the Config screen), and **the
read-only dashboard is already implemented**.

### The approach (agreed by both sides) - **the GUI reads `Field` directly. The documentation stays hand-written, and a test catches any divergence**

**No per-item UI is written.** The shape is such that **the GUI's code does not grow even when this
document's candidates grow by eleven**.

**Neither a parser for the documentation nor a generator of it is needed** - because
**[Field.cs](../../src/core/src/Config/Field.cs) already holds seven of the eight columns**
(**the note at the top of `Field.cs` that it is "settings-matrix.md turned into code"** is the design intent).

| Column | What `Field` holds | How the GUI uses it |
|---|---|---|
| The key | `Scope` / `Key` | Identifies the row |
| CLI | `CliOptions` / `NegatedCliOptions` / `DashOName` (the `-o` name for fstab) | **Shows, in a copyable form, how to write the same setting on the CLI or in fstab** (the route for taking what was changed in the GUI over to fstab) |
| TOML / DB | `SaveTo` (`SaveTarget`) | **Whether it can be persisted.** When it cannot, it says **"for this mount only"** (a remount returns to the toml baseline; the same as File-stored Live in [Pgfsctl.md](../Pgfsctl.md)) |
| The default | `FormatDefaultRaw()` | **Showing the default and "reset to the default".** `config list` already uses it |
| The type | The derived type plus **`EnumField.Allowed`** | Decides the control. `bool` -> a toggle / `enum` -> **a dropdown (the choices are `Allowed` itself)** / a number -> a numeric input / a string -> a text box |
| When it is read | **`Reload` (`ReloadPolicy` = `Live` / `NextMount` / `Format`)** | **Whether applying it live works is answered by this directly.** With `NextMount` it states that **it can be saved but needs a remount** |
| The tooltip | `Comment` ("the description, for generating help and for TOML comments") | **A one-line description.** The same one that appears in `--help` and in the TOML comments |

**Only the `Note` column is absent from `Field` and stays in the documentation.** Because **its content is
prose about trade-offs** ("measured 6.1x with `dd bs=128k` / 1.4x with rsync", "`defer` loses cross-client
exclusion").
**Moving it into the code causes two problems**:

1. **It mixes with `Comment`'s role.** `Comment` is **the one line that appears in `--help` and in the TOML
   comments**, and **putting long prose in makes `--help` unreadable**.
2. **The English-translation surface for develop moves into the code**, which shifts the division of labour with it.

### `settings-matrix.md` stays hand-written and authoritative, plus a test that fails on divergence

**It is not turned into a generated file.** **A hand-written table can be reordered, grouped and marked with
⚠**; a generated one cannot.

Instead, **a test is added that fails when the set of `Field`s and the table diverge**. **What is compared is
only five things - the set of keys / the type / the default / `SaveTo` / `Reload`** - and **the `Note` is not looked at**.

> **This structurally removes "the documentation promising something the implementation does not do".** **That
> is exactly what was hit once**, where **[coding-style.md](coding-style.md) said "machine enforcement works"
> while [.editorconfig](../../.editorconfig) had not a single line for it**. **Comparing gets the same effect
> as generating, without generating.**

### The fallback - hand-writing a screen per item

**Only if something turns up that cannot be built from `Field`.** The price is that **v0.3.0 adds eleven and
more follow**. **The GUI is touched every time one is added**, so **the number of places where the
documentation and the GUI can rot grows.**

### Three things needed either way

- **The default is read-only.** Even once the GUI can write, **it starts read-only** and editing is entered
  explicitly. **An operations dashboard is opened to look at far more often than to change.**
- **An item chosen in full knowledge of how it breaks warns when it is moved off its default.**
  **`mount.hard_remove`** (setting it stops `read` reaching FUSE) and
  **`mount.write_back_flush_extent`** (the trampling) qualify. **Do not merely list them in a dropdown.**
- **Deleting a gravestone (`--forget-tombstone`) does not become a button.**
  **Putting it in the same place as "clean up" (`prune --apply`) causes it to be swept in** - which is exactly
  the reason it was decided on the CLI side **not to fold it into `--apply`**. **Select the gravestone's row
  and do it one at a time, from that row.**
  **The confirmation dialog shows the number of items lost** (what is being deleted is the record of an
  accident, so show what is going).

## The things that are **not** candidates

They are kept separate, because **mixing them in reads as "an option can fix it"**.

- **The attributes of a hardlink not being distributed to its siblings**
  ([data-id-lifecycle.md, the remaining points](data-id-lifecycle.md)) -
  **that is not a choice but something unimplemented.** **It is a matter for a fix, not an option.**
- **The exceptions to the naming convention** (`pgfsctl` / `pgfsgui` departing from `{role}.pgfs`) and
  **the decision not to give some CLI flags a short form** (`--clean` / `--foreground`) - **they change nothing the user sees.**
- **Coding-convention matters** ([coding-style.md](coding-style.md)) - invisible to users.
