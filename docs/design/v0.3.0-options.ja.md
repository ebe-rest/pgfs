## この doc の目的

**ユーザー指示**: **今まで踏んだもののうち、修正はしたが「バグではなく選択」だったものを
オプション化する** + **v0.3.0 で増えたぶんも含めて GUI から細かく設定できるようにする**。

**v0.2.0 には含めない**ことが決着している ([next.ja.md](../next.ja.md))。

## 分類の印

**GUI 側の工数はどれもほぼ同じだが、Core 側の工数が全然違う**ので分けている。

| 印 | 意味 | Core 側の作業 |
|---|---|---|
| **①-a** | いまは固定だが、**内部フラグが既にある** | **設定項目へ昇格させるだけ** |
| **①-b** | いまは固定で、**分岐そのものが無い** | **新規に分岐を作る**。実装も回帰も要る |
| **②** | **既に設定項目だが、既定値の選び方が選択だった** | **既定値と doc だけ**。分岐は既にある |

## 候補 (Linux / 共通 Core 側の洗い出し)

`git grep` し、**利用者から見て挙動が変わるものだけ**を残した
(命名規約の例外やコーディング規約の話は落としている)。

**キー名は提案であって、まだどこにも実装されていない。**

### ①-b — 新規に分岐を作る

| 候補 | 提案キー | CLI | TOML | DB | 既定 | 型 | 参照タイミング | 備考 |
|---|---|---|---|---|---|---|---|---|
| **予約名・末尾の空白/ドットを入口で弾くか** | `assign.reject_invalid_windows_names` | `--reject-invalid-names` | ✅ | ❌ | `true` | bool | `CreateFile` (**新規作成のときだけ**) | **既存は開ける**のが現行の裁定 ([namespace-policy.ja.md](namespace-policy.ja.md))。**Linux から作られた名前を Windows で読めなくしない**ため。**off に倒すと `NUL` や `dot.` を作れる**が、**Win32 の多くの API から触れないファイルができる**。回帰は Windows e2e の `test_ns_*` 3 件 |

### Windows 側で**候補に入れない**もの

| 候補から外したもの | 理由 |
|---|---|
| **`FileIndex` の式** (`data_id \| 0x8000...`) | **Linux の `st_ino` と同じ式であることが、ハードリンクの兄弟判定の前提**である (そう揃えた)。**片方だけ変えられる設定にすると、「Windows からは別ファイル、Linux からは同じファイル」という壊れた組み合わせを作れてしまう。** **選択ではなく不変条件。** |
| **`SetFileAttributes` の ReadOnly が触るビット** | **現行 (write ビットだけ触る) の対案は、直したバグそのもの** (`0444`/`0644`/`0755` へ作り直す = **ディレクトリの traverse 権が落ちる**)。**「選択」ではなく修正**なので入れない。回帰は `test_readonly_dir_keeps_execute` |

## GUI から設定する (Phase 5c の拡張・**設計提案**)

**ユーザー指示の後半**「**v0.3.0 で増えたぶんも含めて GUI から細かく設定できるようにする**」に対する提案。
**まだ合意前**であり、実装は入っていない。**GUI の設計そのものは [gui.ja.md](gui.ja.md) が正**で、
本書には**「v0.3.0 の項目をどう見せるか」だけ**を置く。

**土台は [gui.ja.md](gui.ja.md) の 5c** (config set を Config 画面から) で、**5b (読み取りダッシュボード) まで実装済み**。

### 方針 (両担当で合意) — **GUI は `Field` を直接読む。doc は手書きのまま、食い違いをテストで落とす**

**項目ごとの UI を書かない。** **本書の候補が 11 件増えても GUI のコードは増えない**形にする。

**doc を読むパーサも、doc の生成器も要らない** — **[Field.cs](../../src/core/src/Config/Field.cs) が
8 列のうち 7 列を既に持っている**からである (**`Field.cs` 冒頭の「= `settings-matrix.md` のコード化」**が
設計の意図)。

| 列 | `Field` の持ち物 | GUI での使われ方 |
|---|---|---|
| キー | `Scope` / `Key` | 行の識別 |
| CLI | `CliOptions` / `NegatedCliOptions` / `DashOName` (fstab の `-o` 名) | **同じ設定を CLI / fstab でどう書くかをコピーできる形で出す** (GUI で変えたものを fstab へ持っていく導線) |
| TOML / DB | `SaveTo` (`SaveTarget`) | **永続化できるか。** できないなら**「この mount 限り」**と出す (再マウントで toml のベースラインに戻る。[Pgfsctl.ja.md](../Pgfsctl.ja.md) の File 保管 Live と同じ) |
| 既定 | `FormatDefaultRaw()` | **既定値の表示と「既定に戻す」**。`config list` が既に使っている |
| 型 | 派生の型 + **`EnumField.Allowed`** | コントロールを決める。`bool` → トグル / `enum` → **ドロップダウン (選択肢は `Allowed` そのもの)** / 数値 → 数値入力 / 文字列 → テキスト |
| 参照タイミング | **`Reload` (`ReloadPolicy` = `Live` / `NextMount` / `Format`)** | **live 反映が効くかは、これがそのまま答え。** `NextMount` なら**保存はできるが再マウントが要る**と明示する |
| ツールチップ | `Comment` (「説明文 (ヘルプ自動生成 / TOML コメント用)」) | **1 行の説明。** `--help` と TOML コメントに出るものと同じ |

**`備考` 列だけは `Field` に無く、doc に残す。** **中身がトレードオフの散文**だからである
(「実測 `dd bs=128k` で 6.1× / rsync で 1.4×」「`defer` は cross-client の排他を失う」)。
**コードへ移すと 2 つ困る**:

1. **`Comment` と役割が混ざる。** `Comment` は **`--help` と TOML コメントに出る 1 行**で、
   **長い散文を入れると `--help` が読めなくなる。**
2. **公開 doc の対象がコードへ移り、記述がまとめて動く。**

### `settings-matrix.md` は手書きの正のまま + 食い違ったら落ちるテスト

**生成物にはしない。** **手で書いた表は、並べ替え・グループ化・⚠ の付与ができる**が、生成物はできない。

代わりに **`Field` の集合と表が食い違ったら落ちるテスト**を足す。**突き合わせるのは
キーの集合 / 型 / 既定 / `SaveTo` / `Reload` の 5 点だけ**で、**`備考` は見ない**。

> **これで「doc が実装していない約束をする」が構造的に消える。** **実際に一度踏んでいる**のがまさにそれで、
> **[coding-style.ja.md](coding-style.ja.md) が「機械強制が効く」と書いていたのに [.editorconfig](../../.editorconfig) に
> 1 行も無かった**。**生成しなくても、突き合わせれば同じ効果が出る。**

### 退避先 — 項目ごとに画面を手書きする

**`Field` から作れないものが出てきたときだけ。** 代償は **v0.3.0 で 11 件増え、その後も増える**こと。
**増えるたびに GUI を触る**ので、**doc と GUI の両方が腐る箇所が増える。**

### どちらを採っても要る 3 つ

- **既定は読み取り専用にする。** GUI が書けるようになっても**起動時は read-only** で、
  明示的に「編集」に入る。**運用ダッシュボードは見るために開くほうが多い**ため。
- **壊れ方を承知で選ぶ項目は、既定から外すときに警告を出す。**
  **`mount.hard_remove`** (立てると `read` が FUSE まで来なくなる) と
  **`mount.write_back_flush_extent`** (踏み潰し) が該当する。**ドロップダウンに並べるだけにしない。**
- **墓標の削除 (`--forget-tombstone`) はボタンにしない。**
  **「掃除」(`prune --apply`) と同じ場所に置くと、巻き込みが起きる** — これは CLI 側で
  **`--apply` に巻き込まない**と決めた理由そのものである。**墓標の行を選んで、その行から 1 件ずつ**。
  **確認ダイアログには「失われた件数」を出す** (消すのは事故の記録なので、何を消すのかを見せる)。

## 候補に**入れない**もの

**混ぜると「オプションで直せる」と読まれる**ので分ける。

- **ハードリンクの属性が兄弟に配られないこと** ([data-id-lifecycle.ja.md §残る論点](data-id-lifecycle.ja.md)) —
  **これは選択ではなく未実装**である。**オプションではなく修正の対象。**
- **命名規約の例外** (`pgfsctl` / `pgfsgui` が `{役割}.pgfs` から外れる) や
  **CLI の短縮形を持たせない判断** (`--clean` / `--foreground`) — **利用者の挙動が変わらない。**
- **コーディング規約の話** ([coding-style.ja.md](coding-style.ja.md)) — 利用者に見えない。
