## 決定事項 (合意)

### 決定1: FUSE バインディングを内製化 (`vendor/Tmds.Fuse` submodule / fork を廃止)
- pgfs が **自前の最小 libfuse P/Invoke バインディング** を持つ。submodule と fork は廃止する。
- **内製の理由 (公開用・Tmds.Fuse 作者にも筋が通る形)**:
  1. pgfs は **single-file self-contained** で配布する → 別管理の managed 依存は packaging に反する。
  2. 使うのは FUSE high-level API の **小サブセット (~20 op)** のみ。かつ **pgfs 固有の downstream パッチ**
     (`fuse_config.use_ino` / `fuse_get_context` / mount-option passthrough) を既に抱えており、薄い
     P/Invoke 層のために fork を維持していた状態。
  3. v0.2.0 で **OS 別アセンブリ構成** に移行する → libfuse バインディングは `Pgfs.Fuse` 層 (Linux/POSIX) に自然に収まる。
- libfuse の **C ABI はインターフェース** (バインドするだけ・ソースは vendor しない)。**Tmds.Fuse は
  クレジットする** (NOTICES / history)。LGPL は表に出す必要なし (上記理由だけで十分立つ)。

### 決定2: Lib を OS 層で分割 (`#if` を廃止しアセンブリ境界へ)
開発方針の「共通=親 / 固有=派生」を **アセンブリ境界** で実現する。**OS 層は「FS 機構名」で命名**する
(Windows 側 = `Pgfs.Dokan`)。理由: **Dokan 以外 (WinFsp 等) のパターンも比較検証したい**ので、機構ごとに
別アセンブリを差し替えられる形にする。Linux 側も同方針で `Pgfs.Fuse` (libfuse 機構) とする (決定)。

| アセンブリ | 責務 | 参照する tool |
|---|---|---|
| **`Pgfs.Core`** | OS/機構 非依存の **PostgreSQL/SQL 共通部**: Pg / Api / Config / Models (Inode・Data・Chunk・Audit・**正準 ACL = PgfsAcl・NameNormalizer**) / Logging / Utility。`#if` ゼロ | mkfs・mount・assign |
| **`Pgfs.Fuse`** | Linux (将来 macOS): **自前 libfuse バインディング** + FUSE FileSystem 実装 / PosixAcl 投影 / posix uname-gname resolver | mount |
| **`Pgfs.Dokan`** | Windows: **Dokan バインディング** + Dokan FileSystem 実装 / `win_attrs` / Windows SID・ACL 投影 / WindowsUserResolver | assign |

- **正準 vs 投影**: DB/xattr に入る **正準形** (PgfsAcl・名前ベース ID) は Core、**OS への投影**
  (POSIX mode 適用 / Windows SID 変換) は各機構層 ([permission-interop.ja.md](permission-interop.ja.md) の設計どおり)。
- **命名方針の含意**: 将来 `Pgfs.WinFsp` 等を兄弟として足し Dokan と比較できる。機構非依存の Windows-OS 共通
  (SID/ACL/attrs/`WindowsUserResolver`) の置き場は **詰めポイント3 で決定**: 今は `Pgfs.Dokan` 同居 / WinFsp 追加時に
  `FileSystem.cs` 以外を `Pgfs.Windows` 薄 OS 共通層へ抽出 (YAGNI)。

## 詳細設計 (作業中) — A: Lib 分割

### 階層図 (現案)

```
  tools (薄い exe)
    mkfs.pgfs ───────────────────────────────────┐
    mount.pgfs ──▶ Pgfs.Fuse  (Linux/libfuse) ──┐ │
    assign.pgfs ─▶ Pgfs.Dokan (Windows/Dokan) ──┤ │
                                                ▼ ▼
  ┌──────────────────────────────────────────────────────────┐
  │                         Pgfs.Core                         │
  │             OS/機構 非依存・SQL 共通部・#if ゼロ              │
  │  Pg / Api(inode･data･chunk SQL) / InodeCache / Mode       │
  │  NotifyChannel / RemoteChangeInfo                         │
  │  Config(全 POCO・Loader・Store・Schema・HelpText・Tool)     │
  │  Models(Inode･Data･Chunk･Audit*･正準 PgfsAcl)             │
  │  Logging / Collections / Objects                          │
  │  Utility(PathParser･Retry･Json･Fn･String･NameNormalizer   │
  │          ･ServiceResolver 共通部)                          │
  └───────────────────────────┬──────────────────────────────┘
                              ▼
                        PostgreSQL (Citus 可)

  Pgfs.Fuse 固有:  libfuse binding(内製) / FileSystem(FUSE) /
                   PosixAcl 投影 / posix UserResolver / ServiceResolver posix native
  Pgfs.Dokan 固有: Dokan binding / FileSystem(Dokan) / win_attrs /
                   Win SID･ACL 投影 / WindowsUserResolver / ServiceResolver win native

  外部 system 依存 (非同梱・利用者が用意):
    Pgfs.Fuse  → libfuse.so   (LGPL・dlopen で動的リンク)
    Pgfs.Dokan → Dokan driver (別途インストール)
```

依存方向: **tools → 機構層 (Fuse/Dokan) → Core → PostgreSQL**。Core は上位を知らない。

### ファイル移動先 (確定版・実体照合 2026-06-07)

`src/lib/src` + `src/{mkfs,mount,assign}/src` を実際に列挙して照合した確定移動先 (obj/ 生成物は除く)。

- **Pgfs.Core** (現 Lib の OS 非依存部ぜんぶ):
  `AppInfo.cs` / `Api/{Api,Mode,InodeCache,NotifyChannel,RemoteChangeInfo}` /
  `Collections/{FirstList,RichDictionary,ComparerToEqualityComparer}` /
  `Config/*` (全 POCO + `ConfigLoader` + `ConfigStore` + `Schema` + `HelpText` + `Field` + `Tool` + `SaveTarget`) /
  `Logging/{ILogger,Instance,Logger,LogSink,RotatingFileSink,Level}` / `Objects/Extensions` /
  `Models/{Base,Inode,Data,Chunk,AuditContext,AuditOp,SettingLogging{Cycle,Kind,Output},PgfsAcl(正準)}` /
  `Utility/{Fn,Indexer,Json,PathParser,Pg,Retry,String,NameNormalizer}` + `Utility/ServiceResolver` 共通部。
  ※ `Models/` で Core に行かないのは **`PosixAcl.cs` のみ** (→ Pgfs.Fuse)。`AppInfo.cs` は first cut で漏れていた分。
- **Pgfs.Fuse**: 新 libfuse バインディング(内製) + `mount/FileSystem.cs` + `mount/UserResolver.cs` +
  `Models/PosixAcl.cs` (POSIX ACL 投影) + `ServiceResolver` posix native (`getservbyname`@libc)。
- **Pgfs.Dokan**: `assign/FileSystem.cs` (`IDokanOperations2`) + `assign/FileSystemUtils.cs` + `assign/WindowsUserResolver.cs` +
  `assign/Logger.cs` (**Dokan 確定** = `DokanNet.Logging.ILogger` を実装し `NativeMemory<char>` を処理) +
  `ServiceResolver` win native (`getservbyname`@ws2_32)。
  ※ 将来 WinFsp 追加時に **`FileSystem.cs` 以外** ({`FileSystemUtils`, `WindowsUserResolver`, win_attrs}) を `Pgfs.Windows` へ抽出 (詰めポイント3)。
- **tools(薄い exe)**: mkfs(`Initializer`+`Program`→Core) / mount(`Program`→Fuse+Core) / assign(`Program`→Dokan+Core)。

#### `#if` / OS 分岐の所在 (分割で吸収する対象・実体 grep 済)
**コンパイル時 `#if WINDOWS` は `ServiceResolver.cs` 1 ファイルのみ** = 「#if 廃止」の本丸。残りは実行時 `OperatingSystem.Is*` 分岐。
- `Utility/ServiceResolver.cs` `#if WINDOWS` (×6) = `getservbyname` native (ws2_32 vs libc)。→ 共通部=Core / native=各機構層 (詰めポイント4)。
- `Config/Schema.cs` `IsWindows()?"P:":"/mnt/pgfs"` (既定マウントポイント・実行時三項) → 各機構層が既定を Core へ供給 (詰めポイント5)。
- `Config/ConfigLoader.cs` `if(!IsLinux())` (mount(8) helper-context = `/proc/<ppid>/comm` 判定) → **Core に残す** (runtime guard・非 Linux で benign)。mount(8) 作法という点では Fuse/mount exe 寄りの関心なので、切り出すなら mount 側へ (open detail)。
- `Logging/ILogger.cs` `#if DEBUG` は **OS 非依存** (build config)。→ Core 温存。**「Core は #if ゼロ」は "OS #if ゼロ" の意** (DEBUG 条件は可)。
- 各 `Program.cs` の `OperatingSystem.IsWindows()` ガード (mount↔assign の相互誘導) は各 exe に内包。

### 命名規約 (決定) — ファイル名 / アセンブリ / 名前空間

**2 つのツマミを使い分ける** (現行 csproj が既に採用): 出力ファイル名は `AssemblyName` (小文字 `{役割}.pgfs`)、C# 名前空間は `RootNamespace` (PascalCase `Pgfs.{役割}`)。.NET では「アセンブリ名 = 出力ファイル名」で**同一のツマミ**なので、**PascalCase の `Pgfs.X` は“名前空間 / プロジェクト名”であって厳密にはアセンブリ名ではない**点に注意 (= ファイル小文字と Pascal 名前空間は `AssemblyName`↔`RootNamespace` の分離で両立する)。

| 出力ファイル (= `AssemblyName`) | 名前空間 (= `RootNamespace`) | 種別 | OS 契約 |
|---|---|---|---|
| `core.pgfs`(.dll) | `Pgfs.Core` | lib | 任意 (cosmetic・single-file publish では exe に埋め込まれ姿が消える) |
| `fuse.pgfs`(.dll) | `Pgfs.Fuse` | lib | 任意 |
| `dokan.pgfs`(.dll) | `Pgfs.Dokan` | lib | 任意 |
| `mkfs.pgfs`(.exe) | `Pgfs.Mkfs` | exe | `mkfs` 慣習 (`{action}.{fstype}`) |
| `mount.pgfs`(.exe) | `Pgfs.Mount` | exe | **`mount(8)`/fstab の `/sbin/mount.<type>` 契約 (名前必須)** |
| `assign.pgfs`(.exe) | `Pgfs.Assign` | exe | 任意 (Windows に dispatch 規約なし) |

- **規則**: `Pgfs.{X}` ⇄ ファイル `{x}.pgfs` (全小文字)。アセンブリ名が小文字でも参照解決に支障なし (現行 `lib.pgfs` で実証済み)。
- **`lib.pgfs` → `core.pgfs` にリネーム** (Lib→Core 分割に伴う・v0.2.0 で実施)。
- **`mount.pgfs` / `mkfs.pgfs` の小文字名は必須** (Unix `{action}.{fstype}` 規約・偶然ではなく契約)。
- **`pgfs.assign` 表記の整理 (実施済)**: ビルド成果物は当初から `assign.pgfs` ([Assign.csproj](../../src/assign/Assign.csproj) の `AssemblyName`)。`pgfs.assign` は docs 散文だけの表記揺れだったため `assign.pgfs` に統一済み。

### 詰めポイント
**ステータス**: 1〜7 すべて決定済 (実体照合済)。1〜3 = 重い設計判断 / 4〜7 = 軽い。
1. ✅ **決定: Linux 層名 = `Pgfs.Fuse`** (機構名・`Pgfs.Dokan` と対称)。`Pgfs.Posix` 案は不採用。
   - **理由**: 決定2 の「機構名で命名し差し替え可能にする」と一貫。macOS も libfuse 系 (macFUSE / fuse-t) なら `Pgfs.Fuse` に同居できる。将来 libfuse 以外の POSIX 機構が必要になれば、Windows 側の `Pgfs.WinFsp` と同様、**兄弟アセンブリ**として足す (POSIX 共通層を先に作らない=YAGNI)。
2. ✅ **決定: 「機構=lib + tool=薄い exe」**。各 OS で同形に揃える: {`Pgfs.Fuse` + `mount.pgfs`} / {`Pgfs.Dokan` + `assign.pgfs`}。
   - **理由**: コマンド名を機構から疎結合に保てる → `Dokan`↔`WinFsp` の差し替えを**コマンド名据え置き**で行える (機構名で割った当初の動機を満たす)。`tool exe 自体を機構層にする`案だと比較時に `Pgfs.WinFsp.exe` のようにユーザーが叩く名前が割れてしまう。
   - **依存は一本道**: `tool exe → 機構 lib (Fuse/Dokan) → Core`。Fuse/Dokan は「独立」ではなく Core の**上に乗る差し替え単位**。
   - **tool exe の責務 = OS 呼び出し作法アダプタ**: argv 規約 (mount(8) フラグ飲み込み・位置引数・helper context 判定) / daemonize (子プロセス分離・`Environment.ProcessPath` 自己再起動) / install 名 / PATH 補填。これは機構 (libfuse op) でも Core (OS 非依存 SQL) でもない**固有の関心事**なので薄くても消えない。`mount.pgfs` は `mount(8)`/fstab の `/sbin/mount.<type>` 契約 (=名前必須) も担う ([fstab-support.ja.md](fstab-support.ja.md))。
   - **配布物**: single-file publish が機構 lib + Core を exe に埋め込むため、**配布物は `mount.pgfs` / `assign.pgfs` 1 ファイルのまま** (packaging 後退なし・[決定1](#決定1-fuse-バインディングを内製化-vendortmdsfuse-submodule--fork-を廃止) の self-contained と整合)。
3. ✅ **決定: 今は `Pgfs.Dokan` に同居 / WinFsp 追加時に抽出 (YAGNI)**。
   - **根拠**: SID/ACL/`win_attrs`/`WindowsUserResolver`/`FileSystemUtils` は **Dokan 固有でない** (DokanNet 型を使わず `System.Security.Principal` + `advapi32` + Core の `NameNormalizer`/`Logger` のみ)。だが消費者の `FileSystem`(`IDokanOperations2`) が Dokan 層にいるため、機構が 1 つの今は同居が最小コスト。
   - **抽出単位 (将来 WinFsp 追加時)**: **`FileSystem.cs`(Dokan binding) 以外**を `Pgfs.Windows` (薄い OS 共通層) へ切り出し、`Pgfs.Dokan` / `Pgfs.WinFsp` の両機構が参照する。切り出す塊 = {`WindowsUserResolver` + `FileSystemUtils`(BuildSecurity/ApplySecurity/ToAttributes/IsWritable) + win_attrs}。`Pgfs.Dokan` に残すのは `FileSystem.cs` + `Logger` アダプタ。
   - **exe 案 (`Pgfs.Assign`) は不採用**: 消費者 `FileSystem` が exe を見上げる循環になり `IUserResolver` 注入が必須 + thin-exe 責務 (OS 呼び出し作法のみ) を崩すため。interface も Linux=uid/gid・Windows=SID で漏れる。

**4〜7 (軽い): 実体照合のうえ推し default で確定**:
4. ✅ `ServiceResolver`: Core に interface (knownServices 表 + `/etc/services` パース)、`getservbyname` native impl (ws2_32 / libc) を各機構層から注入。`#if WINDOWS` を撤去しアセンブリ境界へ (= 「#if 廃止」の本丸)。
5. ✅ `Schema` 既定マウントポイント(`IsWindows()?"P:":"/mnt/pgfs"`): 各機構層が既定を Core へ供給し Core から OS 三項を消す。
6. ✅ `assign/Logger.cs` → **Pgfs.Dokan**: `DokanNet.Logging.ILogger` を実装し Dokan の `NativeMemory<char>` を処理する = Dokan 固有アダプタと実体確認。
7. ✅ mkfs: Core のみ参照の薄い tool (`Initializer`+`Program`、FUSE/Dokan 非依存)。変更最小。
